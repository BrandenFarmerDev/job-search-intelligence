## Boundaries

- `app/frontend`: private React/Vite dashboard, accessible charts, searchable applications, timelines, review/corrections/merges/exclusions, sync controls, follow-up recommendations, CSV and deletion.
- `app/backend`: Worker API, D1, durable JobSyncWorkflow, personal Gmail OAuth/read-only ingestion, read-only Sheets API, classification/reconciliation. Dormant Microsoft Graph compatibility remains disabled.
- `packages/shared`: serializable contracts and sixteen-event taxonomy. No credentials enter frontend artifacts.
- `scripts`: deployment isolation guard, dependency audit and unauthenticated Access checks. Legacy Outlook scripts remain only until accepted Gmail cutover and are not an active ingestion path.

Pages and API hosts require owner-email-only Cloudflare Access. The Worker independently verifies RS256 signature, issuer, environment audience, expiry and exact owner email. Every private route is protected; owner mutations require the exact frontend Origin and a non-empty `sub`. `authorize()` returns a principal: the owner, or the automation principal for an Access service-token JWT (`common_name` equal to the `AUTOMATION_CLIENT_ID` Worker secret, empty `sub`, no `email`, `type` `app`; disabled while the secret is unset). Automation must send no `Origin`, is limited to an exact allowlist (`POST /local-outlook/import`, `POST /sync/run`, `GET /sync-runs`; others 403 `automation_route_forbidden`), cannot resume imports paused by typed deletion, queues syncs with trigger `automation` and records `local_outlook_last_automated_import`. Preview/production have separate D1, Worker, Workflow, Access audience, AI Gateway and encryption key. workers.dev and version preview URLs are disabled.

## Frontend

Routes (react-router, all under one shell with a skip link, a collapsible icon-rail sidebar, a mobile Menu overlay and an icon-only Theme control):

| Route | Page |
| --- | --- |
| `/` | Overview: key figures, stage reach, weekly volume, status/reconciliation distributions, insights by source/company/role, follow-ups |
| `/applications` | Filterable, sortable, paginated list; detail drawer; add application; CSV export |
| `/review` | Uncertain source records with decision or exclusion |
| `/sources` | Gmail connection/status, tracker connection, sync history, manual sync/resume/reprocess and typed deletion |
| `/about` | Capabilities and API status |

The shell owns one dashboard provider (`lib/dashboard-context.tsx`): `/dashboard` and `/review` load together, every owner action goes through its `perform`/`runAction`, and a success refreshes all views. Views with their own requests (`lib/use-api.ts`) reload on the provider's revision and abort on change or unmount. A route change moves focus to the page `h1`; the first load does not.

Applications state lives in the URL: `q`, `status`, `source`, `reconciliation`, `from`, `to`, `company`, `role`, `sort`, `page` (zero-based), `pageSize` (25 or 50) and `app` (open drawer). Changing a filter, sort or page size drops `page`; opening or closing the drawer only adds or removes `app`. The drawer loads `/applications/:id` itself, so a deep link works for any record, and closing it restores focus to the opener (or the `h1` for a deep link). Excluding an application uses an inline confirmation inside the drawer rather than a nested dialog. `ApplicationPicker` (merge target, review decisions) searches `/applications` independently of the list filters.

Components: `components/ui` holds the design primitives (Button, Field, SearchInput, StatusBadge, Panel, Kpi, Alert, EmptyState, Skeleton, Tabs, Drawer on native `<dialog>`, DataTable, Pagination, FilterChip). `components/charts` holds hand-written SVG BarChart, ColumnChart and StageReach; each has a Chart | Table switch, and the table lists every value. There are no chart dependencies and no inline styles, because Pages sends `style-src 'self'`.

Styling: semantic `--qe-*` tokens for light and dark in `styles/tokens.css`, ordered by CSS cascade layers in `styles/global.css`. The preference (System, Light, Dark) is stored in `localStorage` key `qe-theme`. `public/theme-init.js` is a same-origin script (inline scripts are blocked by the CSP) that sets `data-theme` on `<html>` before first paint; `lib/theme.ts` keeps it in sync and follows the system setting while System is selected. The same script restores the sidebar state (`data-sidebar` on `<html>`, key `qe-sidebar`), which `lib/sidebar.ts` keeps in sync.

API shapes added for this UI (`packages/shared`): `Dashboard` gained `outcomes` (applied, responses, screenings, interviews, offers, rejections and median response days per source/company/role), `weekly` (UTC Monday-start weekly counts), `medianFirstResponseDays` (nullable) and `lastSuccessfulSyncAt`. `GET /applications` accepts `pageSize` (25 or 50; 50 when absent), `sort` (`applied_desc`, `applied_asc`, `company`, `status`, `updated`; unknown values use `applied_desc`) and exact `company` and `role`, and returns `ApplicationListResponse`: `applications`, `page`, `pageSize`, `total` and `hasMore`.

## Ingestion and reliability

Gmail OAuth uses PKCE, one-use owner/state/cookie/environment bindings, offline access and exactly `gmail.readonly`. Refresh tokens are encrypted with the existing backend token key. Production accepts only `branden.farmer.dev@gmail.com`; preview requires an explicitly different synthetic mailbox. The API never requests send, modify or deletion scope. Native Gmail filters apply the `Job search` root and category labels; application discovery is restricted to that root. Missing/ambiguous labels, multiple lifecycle labels, untrusted alerts, unsupported or attachment-only evidence and unknown job mail fail closed to Review.

Each Gmail Workflow instance has a hard 40-operation envelope: 30 ordinary operations and a 10-operation control reserve. Labels, discovery, metadata, body, classification, Sheets and retention run as separate durable phases. Discovery uses day-sized baseline/weekly-sweep windows plus a seven-day recent window, a captured crawl target, one bounded page per phase and an independent D1-known-ID metadata sweep so label removal, Trash and restored eligibility are observed. Provider failures persist bounded per-candidate attempts and the Gmail path disables automatic step replay. Every Gmail write batch includes generation, connection, selector, pause and lease constraints that fail the batch atomically when stale. Daily phase, projected-instance, Gmail quota-unit/call and D1-row caps stop work before external calls; safe counters expose only totals and error codes.

Existing canonical IDs remain unchanged. Validated Internet Message-ID and bounded evidence supply alias-matching signals, while a new Gmail-only record derives its canonical ID from the mailbox and Gmail message ID. This preserves the 492 existing message records during gap-only historical import from `2026-09-30T07:00:00Z`. Metadata is fetched before bounded bodies. MIME extraction prefers usable `text/plain`, supports a small explicit charset set, sanitizes HTML projection and performs at most one bounded external text-attachment fetch. Normal binary attachments remain metadata evidence and attachment-only messages require Review.

The Microsoft and local Outlook paragraphs below describe retained legacy compatibility and historical evidence. They are inactive during the Gmail cutover and are removed after accepted production flow.

Microsoft OAuth uses PKCE, one-use owner-bound expiring state, a secure HTTP-only callback cookie, consumer authority and offline_access/User.Read/Mail.Read. Refresh tokens use AES-GCM with account-bound additional data and rotate. No Mail.Send permission or sending endpoint exists. Disconnect removes credentials/checkpoints and retains source evidence.

Inbox and Sent Items use immutable Graph identifiers and separate delta links. Source writes and page checkpoints commit atomically. Moves/removals update folder membership/availability without deleting evidence; expired cursors rebaseline their folder. Changed hashes enter a separate classification phase and unfinished records retry. A non-submission email cannot invent an application date: standalone responses require review; linked events retain the email timestamp. Confirmation/submission evidence provides a source-derived applied date, improved by the tracker or owner.

Until Microsoft app registration is available, a Windows-only fallback uses classic Outlook COM. The read-only collector scans direct Inbox/Sent and the explicitly bound Job Search subtree, preserves semantic received/sent membership, evaluates full available plain text locally and exports at most 1,500 characters of useful evidence per item. Generic job alerts stay local. UTC windows and private locator manifests resume bounded discovery; revision caches skip unchanged body reads and seven-day floor reconciliation catches old delayed mail. Incomplete evidence/cache synchronization is reported separately from enumeration completion.

The new client queues DPAPI-protected payloads and acknowledgements, including persistent HTTP 413 child splits. Queue commit precedes scan progress. A server data generation is fetched before discovery and bound to each queue; automated imports require it and fence every batch write atomically. Typed deletion rotates the generation while clearing/pausing data under the maintenance lease. Manual, scheduled and continuation Workflow events carry the generation too, preventing delayed pre-deletion work after reconnect. The authorized sync-history array remains unchanged; its additive `X-Job-Data-Generation` header supplies freshness. The automation route allowlist is unchanged. Manual browser imports remain explicit owner actions. This contract/client release must deploy together while the PC task is paused; legacy automated imports then fail closed.

Canonical evidence identity remains Internet Message-ID or normalized subject/time/conversation/sender; physical cleanup identity is separate. Missing local items never delete D1 evidence. The daily collector never changes mail. A separate one-time cleanup utility inventories direct Inbox/Junk across all dates, creates the approved empty taxonomy, retains Job alerts, and proposes physical-item moves/deletions in an encrypted exact manifest. Actions require owner approval, verified full encrypted MSG backups, isolated restore proof, accepted folder/capture coverage and fresh backend idle evidence. Deletion means a same-store move to Deleted Items, with per-item journals and recovery; no purge or persistent cleanup rule exists. Cleanup and upload share a named mutex and a durable maintenance gate. Provider and installed-release acceptance remain separate from synthetic tests.

Sheets uses spreadsheets.readonly and one configured spreadsheet/range with values:batchGet. Explicit headers map to normalized rows. Natural keys survive reorder; hashes skip unchanged rows, versions retain old snapshots, removals become unavailable, duplicate identities/invalid calendar dates require review. Identity edits retain the old source and create a candidate rather than silently reassigning it. There is no write-back.

Workflow holds a conditional D1 lease, refreshes it and releases it before a bounded continuation handoff. The Gmail phases use the strict operation envelope above; legacy non-Gmail paths retain their historical limits while disabled. A run advances only after its current durable queue is drained, and the final retention phase rechecks candidate backlog and cooldown state before completion. A failed handoff records `continuation_failed` while leaving D1 work recoverable. A new lease holder marks abandoned `running` history as `failed`/`sync_interrupted`. Credentials are read only inside steps, observability is disabled for sensitive outputs, and run history stores safe counters/error codes rather than provider bodies or tokens.

## Classification and canonical records

Explicit text rules run first. Ambiguous/unrecognized job context requires review. Extraction supports explicit field labels and ordinary application phrases. Optional Workers AI receives fixed vocabulary booleans, validates JSON, and always requires human review. Version/input cache and atomic daily reservations prevent repeated calls and excessive retries. AI is disabled with a zero daily cap until free-only execution is verified. No model calls have occurred.

Matching uses ID, requisition/organization, URL, conversation and compatible company/role/date. Multiple candidates, including conversations associated with multiple applications, require review. Current tracker and explicit email status disagreement creates a conflict. Passive confirmations/submissions/follow-ups do not replace current status; lifecycle rank prevents earlier requested stages replacing later scheduled/completed stages. Manual values/associations/exclusions are durable; explicit email status outranks tracker status. Tracker applied dates improve source-derived dates unless manually overridden. Snapshots, decisions, event evidence and owner audit records preserve lineage. Superseded/unreviewed classifications stay in the timeline but do not contribute to analytics.

Analytics exclude excluded applications. Timing averages omit unknown tracker event dates and display a separate unknown bucket. Timelines label observed dates. Computed follow-ups recommend reviewing active applications without a response after seven days; they never send messages. Persisted customizable task scheduling is optional and inactive.

## Privacy and acceptance

Excerpts expire after 30 days, finished runs after 90 days, and expired OAuth state is removed. IDs, subjects, sender references, sheet versions/snapshots, decisions and overrides remain until deletion. CSV formula-leading cells are escaped. Typed deletion removes records/credentials under the lease and durably pauses imports; queued/scheduled runs cannot recreate data until explicit reconnect. Service-account Worker secrets are not removed by record deletion; revoke/rotate external keys separately when retiring access.

Google Sheets production read/replay acceptance is complete. Gmail production consent, refresh, historical gap import, closed-Outlook delivery and unchanged replay remain pending. Live Microsoft Graph is retired from the active plan.
