# API admission and recovery

Every HTTP fetch passes exactly one native `API_RATE_LIMITER` admission decision before origin checks, preflights, authentication, routing, body parsing or effects. Scheduled and internal Workflow execution do not call this HTTP counter. Owner JWT validation and the exact three-route automation service-principal allowlist remain required after admission.

The policy is 300 requests per 60 seconds per trusted client address per Worker environment: local namespace 2007, preview 2008, production 2009. Native counters are approximate and local to Cloudflare locations, not strict global quotas. Missing or invalid `CF-Connecting-IP` values share one sentinel bucket. IPv4 canonical decimal and platform-canonical IPv6 literals are hashed once into a fixed `api:v1:` SHA-256 key. Caller forwarding headers, paths, query strings and identity do not select buckets. Only the existing Cloudflare custom-domain ingress is supported; a future public same-zone Worker proxy invalidates the trusted-header assumption. Shared NAT and cross-zone Worker addresses share capacity.

Explicit success admits. Denial returns JSON 429 `rate_limited`; missing, malformed, throwing, rejecting or stalled bindings return JSON 503 `rate_limit_unavailable`. Binding calls have a 1,000 ms deadline. Both responses carry conservative `Retry-After: 60`, normal security/no-store/CORS headers and bodyless HEAD handling. A late native result may update the native counter, but cannot dispatch application work. Retry-After is exposed alongside X-Job-Data-Generation. No fallback counter or blanket automation bypass exists.

Browser helpers explain readable JSON or HTML 429 responses and admission 503s. Opaque read failures offer connection/wait guidance; opaque write failures say the outcome is unconfirmed and require checking app state before repeating. Each user attempt performs one fetch; cancellation preserves the exact composed signal reason, including interrupted body reads. Interrupted or malformed successful response bodies use the same safe read or unconfirmed-write guidance without exposing parser/transport diagnostics. The existing Outlook uploader alone retains its separate generation-protected 30/60/120/240-second retry, 15-second poll and 25-minute run budget. Durable queue, acknowledgement, generation-conflict and checkpoint behavior are exercised by the existing synthetic lifecycle suite, without Outlook/COM/mailbox/provider access.

The separate shared-zone Free WAF proposal counts `/api` and `/api/` paths across all six hosts at 120 requests per rolling 10-second modeled window, with a 10-second block. It can return HTML and omit CORS or Retry-After. Shared-IP bursts can affect other applications. Disable-only WAF staging is independent of this source release; activation requires affected client fixes released and verified. Never manufacture live bursts to establish enforcement.

## Verification and operations

Use `npm run quality` as the required local gate. It preserves lint, native PowerShell checks, all existing coverage floors, duplication below 3%, generated type checks, strict type checks, build, local additive migrations and zero-vulnerability dependency audit. Added source CodeQL security-extended analysis, source/built Gitleaks scans and fail-closed scanner fixtures repeat in CI. Set `CODEQL_BINARY` and `GITLEAKS_BINARY` to installed official tools when they are not on PATH. Missing PowerShell engines or scanner tools, missing artifacts, malformed reports, incomplete CodeQL execution and findings block the gate. Scans do not establish that all vulnerabilities are absent. CI uses checksum-verified Gitleaks and the official CodeQL setup action. Reviewed secret-scan false positives are only exact public Access AUD IDs at the config path and an exact deterministic synthetic test AES key at three test paths; other credentials still fail the scanner fixtures.

`npm ci` runs `prepare` to install the tracked executable (100755) `.githooks/pre-push`; `npm run test:hooks` verifies the tracked mode, idempotent installation and active setting, and executes the hook against invalid refs. `npm run test:powershell-gate` exercises missing-engine and required-check failure behavior; missing engines fail locally and in CI. Available pwsh runs portable checks, while Windows PowerShell runs native command coverage; unavailable Windows evidence is reported accurately. Every published ref must be an authorized development branch at tested HEAD, with a clean worktree before and after the gate and unchanged publication refs. Do not bypass it. No commit, push, merge or deployment is performed by these tests.

`powershell -NoProfile -File scripts/test-api-rate-workload.ps1` (also `pwsh`) executes actual uploader generation/retry/split/ack code against a synthetic transport, recording timestamped traces in `reports/api-rate-workload.json`. Its exact rolling counters are a deterministic model, not a claim of exact native enforcement. Per-Worker arrivals include only requests that reached the Worker after edge admission; the trace records that disposition separately from the final response. The ordinary scenario assumes one-second synthetic acknowledgements, no provider latency claim, no artificial inter-upload delay, and no preflight caching. It combines six-host visits, concurrent Jobs dashboard/review reads, owner actions and a 250 ms owner search debounce. It emits 100 feasible bounded batches: 50 at the 40-message count boundary and 50 at the 150,000-byte boundary. Production message normalization, merge order and serialization run directly; boundary assertions prove the batches are the unique greedy partition produced by the preparation rule (every nonfinal batch reaches 40 messages or cannot fit its next message). Collector/provider execution is synthetic; this is not maximal real-backlog timing. A separate edge413 variant exercises oversized persisted-style envelopes and real fallback splitting into 100 accepted leaves. Fast variants use 1 ms synthetic acknowledgements plus explicitly labeled stress owner reads and a zone burst; forced import and poll denial exercises all four retry delays. Existing lifecycle tests independently verify durable persistence/resume/conflicts and exhausted-budget behavior. No production workload pacing or capacity guarantee is inferred. Local guard latency evidence uses a warmed immediate binding mock; deployed latency requires later measurement.

The guard emits at most one fixed `api_admission` event with numeric status and fixed denied/unavailable reason. It logs no address, hash, credential, body, path, query, method or exception/provider text. Persistence remains disabled in all environments, invocation logs and traces disabled, query redaction enabled. This deliberately leaves a named operational release gap: platform-attached metadata can contain sensitive OAuth/query context and local console tests cannot validate collected metadata. Before release, inspect actual collected synthetic metadata and configure an authorized safe sink with explicit sampling/retention/ingestion bounds. Do not enable automatic invocation capture or traces blindly. Current account notification policies are empty: sustained returned 503 requires an actionable authorized existing operator route and a verified exercise; routine 429 should be aggregated rather than individually alerted. No recipient, test send or paid service is authorized here.

After approved deployment, verify both environment bindings and namespace separation, trusted ingress, ordinary admitted/authenticated navigation, response hardening and client recovery, deployed latency, privacy-safe collected diagnostics and alert handling. Actual binding readback, ordinary attributable WAF denial/recovery, safe collected-metadata proof and actionable alert exercise remain release blockers. Before rollout record previous Worker deployment/version IDs. Roll back to the prior compatible Worker/client version if needed; this change adds no schema migration. Disable only the owned WAF rule and read it back, preserving unrelated US/Access/IdP controls. No real provider or mailbox actions are required for these source checks.
